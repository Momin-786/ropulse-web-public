# Product screenshots and public-launch readiness

The owner authorized completing the website and sourcing real app screenshots,
then clarified that redesign applies to the website rather than the native app.
This continues the approved website design's product-screen direction.

## Product presentation

Use screenshots rendered by actual RoPulse Flutter widgets with seeded demo
data. Prefer fresh captures from an isolated source snapshot under this web
workspace. If the capture runtime is unavailable, retain provenance for the
app repository's existing widget-test exports instead of inventing UI.

Replace the homepage's conceptual hero with a responsive product composition.
Add a product walkthrough showing Register, table service and checkout. Keep
app screen pixels intact; use website frames, layout and viewport crops for
presentation. Label demo data, preserve currency/amount context and distinguish
recorded payment methods from automatic provider processing.

Record source files, source revision, capture time/type, fixture status and
image hashes in a screenshot manifest. The screenshots do not certify live
backend behavior, production availability or hardware output.

## Launch work

Complete technical readiness fixes that do not require invented business facts.
Separate information-site, enquiry, app-distribution and paid-launch checks
so the public marketing/docs site is not incorrectly treated as requiring
merchant enablement. Preserve the full paid-launch gates from the existing plan.

Prepare one owner-input checklist and reviewable policy drafts. Legal seller
identity, jurisdiction, actual contacts, domain/hosting ownership, approved
commercial terms and merchant access remain factual owner inputs. No secret
should be committed or requested in plain chat. Do not mark draft terms or
unverified installer signatures as approved merely to pass a launch check.

## Verification

Test screenshot assets/provenance, responsive layouts and image loading; retain
manual publication isolation and honest disabled-service behavior. Run unit
tests, type checking, production build and browser checks after changes.
